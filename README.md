# 📦 扩展管家 (Extension Butler)

`扩展管家` 是一款为 Google Chrome 浏览器定制的轻量级、超高效率的扩展管理工具。它允许您直接通过网页上的右键上下文菜单，极其便捷、静默地启用或禁用浏览器中的其他扩展程序，完全不打断您当前的工作流。

---

## 🌟 核心特性

* **🔍 全场景右键支持 (`contexts: ["all"]`)**
  * 不仅支持在网页空白处右击显示，还支持在图片、选中文本、超链接、输入框等任何元素上右击调出控制菜单。
* **🔤 已启用项置顶 + 智能混合字母排序**
  * **状态分组**：已启用的扩展始终排在菜单最前，已禁用项沉到下方；任一项切换状态后会自动重排（顺序确实变化时才重建菜单，末尾项切换仍走零闪烁的增量更新）。
  * 采用基于 `Intl.Collator` 的中文拼音排序引擎（`new Intl.Collator('zh-Hans-CN-u-co-pinyin', …)` 惰性创建单例复用，避免每次比较重复解析 locale）。组内按拼音/字母的 **A-Z** 自然排序，英文与中文混合排列时井然有序。
  * 智能数字识别（Numeric Collation），使 `"Item 2"` 自然排在 `"Item 10"` 前面。
* **🔤 名称精确显示（`&` 转义）**
  * 扩展名中的 `&` 会被自动转义为 `&&`，避免被右键菜单解析为快捷键助记符后出现 `&` 被吞掉、后续字符带下划线的显示错乱。
* **🚧 策略扩展过滤**
  * `mayDisable === false`（企业策略安装等无法由用户禁用）的扩展不会进入菜单，避免出现点击后无法切换的无效菜单项。
* **⚡ 极致性能与零闪烁（异步控制）**
  * 完美适配 Chrome Manifest V3 (MV3) 生命周期。
  * **增量更新机制**：启用/禁用单个扩展时，先比对重排后的顺序——顺序未变（如末尾项切换）只 `chrome.contextMenus.update` 单点改图标，避免闪烁；顺序需要变化（启用项上移）才整表重建，兼顾正确性与性能。
  * **并发安全控制**：内置 `isRefreshing`/`pendingRefresh` 异步并发锁，消除快速点击时的竞态条件（Race Condition）和 `duplicate id` 报错。
* **🛡️ 自动容错与重试**
  * 增量更新失败时自动降级为全量刷新，确保菜单状态永不偏离。
  * 全量刷新内置 **最多 3 次自动重试** 机制（初次尝试之外再重试 3 次，共 4 次尝试），并采用 **指数退避**（第 n 次重试延迟 n × 250ms），避免背靠背重试对瞬时故障无效。
  * 重试系列放弃后不把菜单留在“已清空未重建”的破损状态：自动安排 **最多 3 轮延时自愈**（间隔 5s）；连续自愈仍失败才暂停，等待下一次生命周期事件兜底。事件触发的新刷新会重置重试预算，独立的故障不会被跨周期累计。
  * 子菜单创建失败同样计入重试；配合**轮次代号（generation）**机制丢弃过期轮次的迟到回调，防止旧轮回调污染新一轮刷新的状态锁。
* **🧠 扩展状态记忆（JSON 快照）**
  * 任何启用/禁用变化（右键菜单、面板、或直接在 `chrome://extensions` 操作）都会写入 `chrome.storage.local` 的 `stateMemory` JSON 快照，含 `name` / `enabled` / `ts`。
  * 扩展被**重新安装或更新**（`management.onInstalled`）时自动套用记忆：之前被你关掉的扩展，重装后仍是关闭状态，无需再手动关一遍。
  * **卸载即墓碑**：`management.onUninstalled` 会把该 ID 标记为 `deleted: true`（写墓碑而非删除键），条目仍留在快照中但被忽略；这样删除动作能同步到云端与其它设备，不会被旧快照复活。
  * **跨设备恢复**：快照以云端（Cloudflare Worker + KV）为主，首次安装 / 换浏览器加载时自动从云端拉取并按记忆恢复各扩展开关；未配置云端时只保存在本机 `chrome.storage.local`。
  * **主动补录**：安装、更新、浏览器启动时（`onInstalled` / `onStartup`）会遍历全部扩展补录一次快照，所以云端不会是空的，也无需先手动切换一次。
  * **缺失扩展提醒**：本地记忆（与云端同步后一致）中记录但当前浏览器没装的扩展，会在面板中列出；点击每行右侧的「安装 ↗」打开其商店页，点「全部安装 ↗」则在新窗口一次性打开全部商店页，装完自动恢复开关状态。工具栏图标角标同步显示缺失数量。
  * 受 Chrome 硬限制（MV3 已移除 `chrome.webstore.install`），扩展**无法静默安装其他扩展**；确实需要静默批量部署只能用企业策略 `ExtensionInstallForcelist`（写注册表，需管理员权限，Chrome 会显示「由组织管理」）。
* **☁️ 云端同步（可选，Cloudflare Worker）**
  * `worker/` 内提供了基于 Workers + KV 的极简 API：`GET /state` 读取、`PUT /state` 覆盖写入，Bearer TOKEN 鉴权，CORS 全开。
  * Worker 的 KV namespace `STATE` 的 ID 属于环境相关信息，不写入仓库：`wrangler.toml` 中使用占位符 `<KV_NAMESPACE_ID>`，真实 ID 保存在本地 `worker/mima.txt`（已忽略提交），部署前填入。服务端 TOKEN 用 `wrangler secret put TOKEN` 维护；Worker 访问地址与 TOKEN 同样由本地 `worker/mima.txt` 提供（popup 启动读取），请勿提交到版本库。
  * 打开面板即自动读取 `worker/mima.txt` 的地址与 TOKEN 登录（失败则回退本机已存配置），无需手动填入；底部云端图标旁以文字显示「已登录 / 未登录 / 同步失败」。登录后**状态快照以云端为主**：每次开关变化会在 1.5s 防抖后自动 `PUT` 上云；首次安装 / 换浏览器加载时从云端恢复。
  * **全自动、无需手动配置**：从 `worker/mima.txt` 读取地址与 TOKEN 后自动「拉取合并 → 上传回写」完成双向同步；此后面板每次打开也会自动同步一次（60s 节流），状态变化由 background 1.5s 防抖推送。缺失扩展列表读本地 `stateMemory`（与云端同步后一致）。地址与 TOKEN 主存于 `worker/mima.txt`，读取成功后会缓存到本机 `chrome.storage.local.cloudConfig`。
* **⚡ 性能与内存**
  * 面板复用行节点：状态切换只改 class 与顺序，不重建 DOM；批量操作的事件风暴按 60ms 合并，只重绘一次。
  * 缺失列表直接读本地记忆，不额外发请求；云端自动同步带 60s 节流。
  * background 侧：记忆落盘 200ms 防抖、云端推送 1.5s 防抖，角标统计走内存快照，避免重复的 `getAll` 与云端往返。
* **🫧 胶囊控制面板（Popup）**
  * 点击工具栏图标弹出深色胶囊面板：扩展以两列网格排列，每行是胶囊卡片（首字徽章 + 名称 + 开关），点击即切换启用状态；左下角实时显示「已启用 / 总数」，与右下角云端状态同一底边对齐。
  * 行右侧的**垃圾桶按钮**可卸载该扩展，走浏览器原生确认框（`management.uninstall({ showConfirmDialog: true })`），取消则静默无副作用。
  * 面板顶部「后台持续播放」开关左侧并排两个紧凑胶囊按钮：`全部开启`（绿色，全部已启用时置灰）与 `全部关闭`（红色，全部已关闭时置灰），批量静默切换；面板存活期间监听 `management` 事件，别处变化即时反映。
* **🎬 网页视频后台持续播放**
  * 面板内开启后，向所有站点注入 MAIN world 脚本，让页面始终认为自身「可见且在前台」：`document.hidden` 恒为 `false`、`visibilityState` 恒为 `visible`，并拦截 `visibilitychange` 与窗口级 `blur`，切换标签页/窗口时播放器不会主动暂停。
  * **默认开启**：动态注册脚本并对已打开标签立即注入；在面板中关闭时立即还原页面原型并注销脚本，无需刷新（仅显式关闭后才不再注入）。
* **🚫 一键关闭全部扩展**
  * 菜单末尾固定提供 `🚫 一键关闭所有扩展`，一次点击静默禁用所有可管理且当前启用的扩展（跳过主题、不可禁用项与自身，已禁用的不重复处理）。
  * 关闭结果由 `management.onDisabled` 驱动同步，最终按「已启用置顶」的规则重排菜单。
* **🔇 纯粹的静默交互**
  * 彻底移除了传统扩展在开启时会自动弹出新标签页的烦人干扰，所有切换操作完全静默、流畅，瞬间完成。
  * 弹窗面板内屏蔽浏览器原生右键菜单，避免在面板上误触；网页中的右键菜单仍是本扩展的功能入口，不受影响。
* **📋 友好的空状态处理**
  * 当浏览器中无其他可管理的扩展时，菜单项显示 `🔌 无其他可管理扩展` 占位提示，避免右键菜单被意外清空。
* **🔍 调试日志支持（默认关闭）**
  * `background.js` 顶部常量 `DEBUG` 默认为 `false`，需要排查时改为 `true` 并重新加载扩展；Service Worker 控制台会输出扩展列表信息（名称、启用状态、类型、安装来源）等对账细节。

## ⚙️ 安装与调试指南

如果您需要将此扩展安装到浏览器中或进行开发调试，请按照以下步骤操作：

1. **打开扩展程序管理页面**
   * 在 Chrome 浏览器地址栏中输入 `chrome://extensions/` 并回车。
2. **开启“开发者模式”**
   * 在页面右上角，找到 **“开发者模式” (Developer mode)** 开关并将其**启用**。
3. **加载扩展程序**
   * 点击页面左上角的 **“加载已解压的扩展程序” (Load unpacked)** 按钮。
   * 选择本项目所在的文件夹（即 `管理扩展` 目录）。
4. **重新加载与更新**
   * 后续如果修改了 `background.js` 或 `manifest.json`，只需在扩展卡片上点击右下角的 **“重新加载” (🔄/Reload)** 按钮，即可瞬间应用更新。
5. **云端同步（可选）**
   * Worker 地址与 TOKEN 来自本地 `worker/mima.txt`（已加入 `.gitignore`），面板启动时自动读取并登录，无需手动填入；没有该文件时扩展只使用本机状态记忆。

## 🔒 浏览器技术局限说明

> [!NOTE]
> **关于右键菜单二级菜单项的图标显示说明**
> 根据 Google Chrome 浏览器的安全与设计规范，`chrome.contextMenus` API **不支持**在子菜单（二级菜单）中为每一项显示自定义的图片图标。
> * **安全限制**：此项限制旨在防止恶意扩展伪造浏览器原生菜单或其他敏感系统的图标来进行钓鱼攻击。
> * **当前方案**：我们采用了现代、高对比度的 Emoji（`🟢` 表示已启用，`🌑` 表示已禁用）作为视觉指示符，以最轻量优雅的方式提供状态反馈。

> [!NOTE]
> **冷启动对账的“清单比对 + 逐项探测”**
> 对账分两级工作：先与上次全量刷新落盘到 `chrome.storage.local` 的“应存在菜单项 id 清单”比对，id 集合不一致（禁用窗口期错过的安装/卸载，包括探测法无法发现的“幽灵”残留项）直接全量重建；一致时再逐项探测，顺带同步最新名称与状态图标、发现缺失项。清单缺失或读取失败时自动退化为纯探测路径，不影响菜单本身。

> [!NOTE]
> **状态快照的存放位置**
> 快照结构为 `{ "<扩展ID>": { "name": "...", "enabled": false, "ts": 1700000000000, "deleted"?: true } }`，其中 `deleted: true` 表示卸载墓碑（条目保留但忽略）。配置云端后，主体存放在 Cloudflare KV（`state` 键），本机 `chrome.storage.local.stateMemory` 是读写缓存；未配置云端时仅存本机。

> [!NOTE]
> **后台持续播放的能力边界**
> 该功能只改变页面能感知到的「可见性 / 焦点」状态，无法绕过浏览器自身的媒体策略：例如 Chrome 对长期静音标签页的暂停行为、系统级音频中断（切到其他音频设备/被电话占用）。若播放器使用私有检测手段（Web Worker 计时、Media Session 等）仍可能自行暂停。另外，开启后需要该站点重新加载过页面才会生效，脚本已对已打开标签主动注入，失败（如 `chrome://` 页面）会被静默跳过。

## 🔄 生命周期与状态同步机制

扩展管家通过精细的事件监听实现高效的状态同步：

| 事件 | 处理方式 | 说明 |
|------|----------|------|
| `runtime.onInstalled` / `runtime.onStartup` | **全量刷新** (`removeAll` → `create`) | 本扩展安装、更新以及浏览器启动时完整重建菜单 |
| `management.onEnabled` / `management.onDisabled` | **顺序比对**：不变则增量更新，变化则全量重排 | 已启用项置顶，切换后自动上移/下沉；仅末尾项切换时走零闪烁的 `contextMenus.update` |
| `management.onInstalled` (其他扩展安装/更新) | **先按记忆恢复状态** + 全量刷新 | 记忆为禁用则自动 `setEnabled(false)`；列表数量变化时重新排列所有项 |
| `management.onUninstalled` (扩展卸载) | **全量刷新** | 列表数量变化时需要重新排列所有项 |
| Service Worker 冷启动（含本扩展被禁用后重新启用） | **轻量对账**（清单比对发现幽灵/缺失项 → 全量重建；一致则逐项 `contextMenus.update` 探测并顺带同步名称/状态） | 修正禁用窗口期内错过的安装/卸载等变化，菜单一致时零重建 |
| `onClicked` | **切换启用状态** | 点击扩展项时调用 `management.setEnabled` 切换扩展状态 |
| `onClicked`（`disable-all`） | **一键关闭** | 取 `management.getAll` 结果中对已启用且可管理的扩展批量 `setEnabled(false)`，状态图标由 `onDisabled` 增量同步 |

> **监听过滤**：所有 `management` 事件均排除本扩展自身（`id !== chrome.runtime.id`），且仅处理 `type === "extension"` 的普通扩展，主题等其他类型不会进入菜单；`mayDisable === false`（企业策略安装等无法禁用）的扩展同样被排除。
> **增量更新失败降级**：若 `chrome.contextMenus.update` 因菜单项丢失等原因失败，会自动回退到全量刷新，保证菜单状态最终一致。
> **并发安全**：全量刷新进行中或已有重建在排队（重试退避/自愈窗口）时，增量更新请求会被暂存（`pendingRefresh` 标记），待重建完成后自动以最新全量状态生成标题，保证菜单状态最终一致，避免竞态条件。
> **重试机制**：全量刷新在 `removeAll`、`getAll`、菜单创建等任何阶段失败时都会自动重试，最多重试 3 次（指数退避：第 n 次重试延迟 n × 250ms），避免因浏览器 API 瞬时故障导致菜单丢失；重试系列被放弃后会自动安排最多 3 轮延时自愈（间隔 5s），且事件触发的新刷新会重置重试预算，独立故障不会被跨周期累计。
